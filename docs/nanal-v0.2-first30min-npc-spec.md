# Nanal — 첫 30분 플레이·NPC 자율성 설계 v0.2

- 상태: 첫 주 웹 프로토타입 구현 기준
- 목표: 세션 시작 30분 안에 캐릭터 설정, 첫 사건, 주간 행동, 관계 변화, 다음 주 궁금증까지 경험한다.
- 대상: 스마트폰 세로 화면 우선
- 범위: 2020–2026 시작 연도, 성인 19–30세, 대학생·취업준비생·직장인
- 제외: 초상화/이미지, 유료 API, 서버·계정, 현실 통계인 것처럼 보이는 미검증 수치

## 1. 첫 30분 플레이 흐름

| 구간 | 플레이 | 설계 의도 |
|---|---|---|
| 0–3분 | 이름·나이·연도·배경 선택 후 시작 | 입력을 최소화하고 배경별 출발 차이를 먼저 보여준다. |
| 3–7분 | 현재 목표와 생활 상태 확인 | 돈·에너지·긴장도·준비도를 읽고 “지금 내 상황”을 파악한다. |
| 7–15분 | 배경별 첫 사건에서 2–4개 대응 중 선택 | 선택은 서로 다른 비용·관계 결과를 남기며 정답을 노출하지 않는다. |
| 15–23분 | 주간 행동 두 개 선택 | 배움·일·교류·휴식·운동·기회 탐색 중 이번 주 우선순위를 정한다. |
| 23–26분 | 주간 정산 | 수입·생활비·상태 변화와 NPC의 자율 행동을 한 화면에서 확인한다. |
| 26–30분 | 인물·성장·기록 탭을 살펴보고 다음 주 진입 | 내가 놓친 변화와 다음 주에 이어질 일을 찾게 한다. |

### 첫 주를 기억하게 하는 기준

- 사건 도입은 캐릭터 설정과 배경에 맞는다. 특정 주요 사건이 반드시 발생한다고 약속하지 않는다.
- 선택 즉시 바뀐 수치·관계와 원인을 보여준다.
- NPC가 플레이어의 행동을 기다리기만 하지 않고 자기 목표를 한 단계 진행하거나, 사정 때문에 계획을 미룬다.
- 조용한 주도 정상적인 플레이 결과로 취급한다.
- 세 배경은 같은 시간·행동·저장 규칙을 사용하되, 첫 사건과 인물 목표가 달라야 한다.
- 이번 프로토타입의 30분은 플레이 흐름의 설계 기준이다. 실제 소요 시간은 기기와 읽는 속도로 검증한다.

## 2. NPC 최소 자율성 모델

### NPC 상태

각 핵심 NPC는 다음 상태를 가진다.

- 안정 ID, 이름, 나이, 역할
- 플레이어와의 친밀도(-5–5) 및 신뢰도(0–100)
- 현재 기분과 이번 주 마지막으로 한 일
- 목표 제목, 진행 단계(0–3), 현재 이정표
- 플레이어와 공유된 기억 목록: 내용, 발생 주, 선명도(0–1)

NPC의 역할·목표는 서로 맞아야 한다. 관계 인물의 이름과 성별 표현도 일관성을 유지한다. 캐릭터별 초상·이미지는 이 기능의 필수 조건이 아니다.

### 주간 자율 처리

매주 진행을 확정할 때 NPC별로 한 번 자율 행동을 계산한다.

1. 현재 목표와 상태를 기준으로 목표를 이어갈지, 계획을 미룰지 결정한다.
2. 진행한 경우 이정표와 마지막 행동을 갱신한다.
3. 목표가 한 단계 완료되면 기록에 남기고 기분과 기억에 반영한다.
4. 목표 완료나 환경 변화가 있을 때 새 목표 후보를 만들 수 있다.
5. 플레이어 행동이 그 주 NPC를 직접 건드렸다면 해당 관계·기억에 후속 반응을 남긴다.

첫 구현은 모든 NPC의 세부 일정을 매일 계산하지 않는다. 주간 단위로 핵심 NPC 상태만 갱신해 모바일에서도 가볍게 실행한다. 브라우저를 닫은 동안 게임 시간은 흐르지 않는다.

### 목표 변경 규칙

- 플레이어 목표는 사용자가 직접 바꾸기 전에는 자동 교체하지 않는다.
- NPC 목표는 배경·역할·현재 생활과 일관된 후보에서만 바꾼다.
- 목표 변경에는 이유가 있어야 한다. 목표가 완료됐거나, 기존 계획이 오래 막혔거나, 관계·일·생활 사건으로 우선순위가 달라진 경우에만 허용한다.
- 같은 목표를 반복해서 임의 재설정하지 않는다. 변경 후에는 이전 목표와 이유를 기록한다.
- 진행률을 근거 없이 백분율로 표현하지 않고, 이정표·다음 행동 중심으로 보여준다.

### 기억 흐림

- 행동과 사건의 중요한 기억은 처음에는 선명하게 남는다.
- 시간이 지나며 선명도가 낮아지고, 낮은 선명도의 세부 기억은 NPC의 활성 기억 목록에서 제거될 수 있다.
- 기록 탭의 인생 로그와 NPC가 지금 생생하게 떠올리는 기억은 별도 데이터다. 기억 흐림이 역사 기록을 지우지 않는다.
- 가까운 관계·반복된 사건·강한 감정의 기억은 더 오래 남길 수 있다. 첫 프로토타입에서는 단순 감쇠를 사용하고 후속 밸런스에서 맥락 가중치를 조정한다.

## 3. 사건·선택과 자율 행동 연결

- 사건 조건과 결과는 게임 엔진이 결정한다. 화면 렌더링은 난수를 소비하지 않는다.
- 같은 저장 상태·엔진 버전·선택 순서이면 같은 결과가 재현돼야 한다.
- 선택지는 보통 2–4개이며, 각 선택의 비용·장점·불확실성을 짧게 설명한다.
- NPC가 참여한 선택은 그 NPC의 관계 수치와 기억을 함께 갱신한다.
- 선택 후에는 실제 상태 차이와 원인만 보여준다. 숨은 확률을 결과처럼 제시하지 않는다.
- 사건이 진행 중이면 행동·시간 진행을 막아 중복 처리와 날짜 건너뛰기를 방지한다.

## 4. 이번 구현 범위와 다음 확장

### 첫 구현에 포함

- 브라우저 로컬 저장, JSON 저장 내보내기·불러오기
- 배경별 시작 캐릭터·첫 사건·핵심 NPC
- 사건 선택, 주 2회 행동, 주간 수입·지출
- NPC 목표 진행, 상태·기억 갱신, 변경 로그
- 생활·인물·성장·자산·기록의 고정 하단 탭
- 모바일 세로 화면, 키보드 포커스·터치 영역 기본 대응
- 결정론적 난수와 엔진 단위 테스트

### 후속 단계

1. 첫 주 사용성 점검과 버튼·사건·결과 피드백 수정
2. 첫 달 진행, 월말 정산, 수입·지출 항목의 배경별 차이
3. NPC 목표 생성·변경 사유, 관계별 정보 공개와 기억 선명도
4. 직업·학업·가족·주거·생활비를 서로 연결
5. 시간·일 단위로 확대할 필요가 있는 주요 사건에만 세분 진행 적용
6. 현실 통계는 출처·기준 연도를 검증해 연결
7. 초상화는 별도 이미지 자산 계약이 준비된 뒤 추가

## 5. 완료 판정

- 세 배경 각각 새 게임부터 첫 주 정리까지 플레이 가능하다.
- 사건 전 선택을 진행할 수 없고, 한 선택의 효과는 한 번만 반영된다.
- 주간 행동 두 개를 사용하기 전에는 주를 닫을 수 없다.
- 주간 종료 때 NPC 목표·기분·최근 행동·기억 중 하나 이상이 조건에 맞게 갱신된다.
- 저장 후 새로고침해 날짜, 상태, 관계, 대기 사건이 보존된다.
- JSON 저장 파일을 내보내고 다시 불러올 수 있다.
- 같은 시드와 선택 순서로 같은 결과를 재현한다.
- 390×844 화면에서 주요 버튼·선택지가 가로 넘침 없이 눌린다.
- 화면의 임시 금액과 사건 확률을 현실 통계로 오인하지 않도록 밸런스 안내를 표시한다.
