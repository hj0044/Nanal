# Nanal — 반실사 NPC 외형 엔진 재설계 v2 (설계안)

작성 기준: 2026-10-22. **설계 제안이며 구현·병합·실기기 검증을 의미하지 않는다.**

## 0. 결정 사항 (ADR)

- **선택: AI 보조 에셋 제작 + 엄격한 공통 규격 + 실제 마스킹 레이어 합성 + 승인 후 WebP 제공**.
- AI 모델은 에셋 생산 도구일 뿐이다. 게임 실행 중 AI 생성 API를 호출하지 않는다.
- **고정 정보: 얼굴 고유 형태, 기준 두상과 특징점, 신체 비율**. **변경 가능 정보: 헤어스타일, 머리색, 의상, 액세서리, 시간에 따른 노화 표현**.
- 결과물은 **동일 인물의 얼굴 픽셀이 고정된 채 실제 헤어 실루엣/의상 형태가 달라져야** 한다.
- 잘못된 v1–v3 데모에서 행했던 사진 전체 교체, 사각형 착색, 성별 불일치, 검증되지 않은 96가지 '조합' 주장을 다시 사용하지 않는다.
- **독립적인 2×2×2 검증**(남·여 각 1명 × 서로 다른 실제 머리모양 2종 × 다른 실제 옷 디자인 2종)을 통과하기 전 대량 이미지 제작을 금지한다.

## 1. 현재 Nanal의 제약과 마이그레이션

- React 19 + TypeScript + Vite 기반 모바일 우선 정적 앱.
- src/portrait-catalog.ts의 portraitCatalog는 단일 이미지 혹은 4×4 atlas를 선택하는 모델. 일부 SourceAsset에는 hairId/outfitId가 있지만 런타임은 그 값으로 이미지를 합성하지 않는다.
- src/game.ts의 Character와 Contact에 portraitId가 있다. src/main.tsx가 게임 저장을 version=1 키(nanal-save-v1)로 읽고 portraitId를 정규화한다.
- 현재 개별 초상화 카탈로그는 20–39세를 우선 필터링하므로, 어린이·중년·고령 NPC의 연령 적합성을 해결하지 못한다. 사전 승인된 연령군별 에셋으로 확장한다.
- 플레이어/NPC 신상/관계/기억/보관/재등장은 이미지 리소스가 아닌 시뮬레이션 ID에 계속 연결한다.
- 기존 게임 로직과 세이브는 파괴적으로 교체하지 않는다. v2 필드 추가 → 이중 렌더러 → 검증 → 선택적 전환 → 구 렌더러 제거 순서.

## 2. 아트 규격과 계층

- 1024×1024 RGBA 마스터, 같은 카메라(정면 혹은 동일한 3/4), 시선, 자세(상반신), 확산광, 표정 중립. 모든 마스크는 마스터와 픽셀 정렬.
- 성인 남/여, 두상 형태(예: 3 계열), 체형(3 계열)은 호환성 테이블을 만든다. 아동/청소년/노년은 단일 성인 템플릿에 강제하지 않고 별도 규격/얼굴 팩을 둔다.
- 레이어: (1) 뒷머리 (2) 신체·목 (3) 의상 후면 (4) 의상 본체 (5) 고정 얼굴 원본 (6) 앞머리 (7) 옷깃/교차하는 의상 전면 (8) 액세서리 (9) 전용 접촉 그림자.
- 헤어는 front/back뿐 아니라 **머리카락 가림 마스크(귀/이마)** 와 전용 contact shadow를 제공한다. 의상은 체형별 어깨/목깃 경계 및 손/팔 가림 관계를 포함한다.
- 피부색과 목은 얼굴/몸의 색조 일관성을 맞춰야 한다. 각 파츠는 투명 배경 외부로 그림자를 확장하지 않는다.
- AI가 만든 결과는 마스크 모양을 완전히 따르지 못할 수 있으므로 오프라인에서 alpha matte, 강제 클립, 간단한 핸드 리터치까지 마친 뒤 **승인된 PNG 파츠**로 등록한다.
- **결과 이미지를 색상 필터로 가짜 변장시키지 않는다.** 색상 변경은 별도의 옷감 영역 마스크, 실제 형태 변경은 다른 완성된 의상 파츠로 표현한다.

## 3. 파츠 생성 파이프라인

1. artStyleVersion별 기준 캐릭터 2명(남·여)을 정하고 정면/조명/선화/질감/배경을 잠근다.
2. 얼굴 마스터마다 faceId와 headShapeId, 랜드마크, 정면 얼굴 코어 보호 마스크를 만든다.
3. AI 편집으로 새 머리모양과 의상 디자인을 **각각 실제로 생성**하되 얼굴 코어 영역은 절대 재작성하지 않는다. 얼굴 코어가 편집돼도 원본을 강제로 되돌린다.
4. 헤어 front/back, 의상 front/back, 가림·접촉 그림자, 체형 관련 파츠를 추출/리터치한다.
5. PNG 소스의 크기/알파/앵커 검증, 레이어 합성 → 사전 승인된 조합을 WebP로 출력한다.
6. 연락시트에서 사람 검수: 얼굴 동일성, 헤어라인, 목, 옷깃, 귀, 광원, 비대칭/일러스트 톤.
7. 승인 서명과 SHA-256 검사를 통과한 파츠만 publish manifest에 기록. 미승인 소스/프롬프트/API 키는 앱으로 배포하지 않는다.
8. Nanal 런타임은 승인 WebP를 CDN에서 로딩한다. 커스터마이징 화면에 한해 제한된 Canvas 레이어 미리보기를 사용하고 최종 결과는 캐싱한다.

### 예외 처리

- 옷깃·포니테일·후드처럼 파츠를 독립 합성하면 품질이 무너지는 조합은 별도의 손수 보정된 예외 에셋으로 보유한다.
- '실사스럽게' 생성한 원본들이 서로 이질적이면 자동 통과시키지 않고, 동일 스타일 지침과 사람 평가 후 재제작한다.
- 촬영 사진으로 바뀌는 실사/반실사 혼재는 불합격. 렌더 스타일 자체가 동일한 디지털 페인팅이어야 한다.

## 4. 도메인 모델과 저장 계약

TypeScript 제안(구 필드를 즉시 삭제하지 않는다):

~~~ts
type AppearanceV2 = {
  schemaVersion: 2;
  artStyleVersion: "semi-real-v2";
  identitySeed: number;        // 동일 게임 내 캐릭터 고유, 재회해도 불변
  faceId: string;              // 고정
  headShapeId: string;         // 고정
  bodyFrameId: string;         // 캐릭터 체격 기준, 성장/변화 이벤트로만 변경
  skinPaletteId: string;       // 고정
  hairStyleId: string;         // 변경 가능
  hairColorId: string;         // 변경 가능
  outfitId: string;            // 변경 가능
  accessoryIds: string[];      // 변경 가능
  ageStageId: string;          // 연령군 전환 검수 후 변경
};

type AppearanceManifestEntry = {
  assetId: string;
  kind: "face"|"hairFront"|"hairBack"|"body"|"outfit"|"shadow"|"accessory"|"composite";
  artStyleVersion: "semi-real-v2";
  headShapeId?: string;
  bodyFrameId?: string;
  ageStageIds: string[];
  genderTag?: "남성"|"여성";    // 제작/호환성 검수용 메타데이터
  url: string;                  // 버전 지정된 공개 CDN URL
  sha256: string;
  approved: boolean;
};
~~~

- 게임의 person.id / game seed로 identitySeed를 결정적으로 할당하되 구분자에 게임 고유값을 넣는다. 새 게임/세이브는 외형 조합이 독립적.
- 저장된 appearanceV2가 있으면 다시 추첨하지 않는다. archivedContacts와 재등장 인물에도 그대로 유지.
- 체형·나이·직업·경제력 변화는 이벤트가 '변경 가능한 외형 정보'만 수정한다. 직업만 바뀌었다고 얼굴 재생성하지 않는다.
- 이름/소속/성격은 미술 카탈로그에서 분리. NPC 개수는 리소스 수와 무관. 원본 얼굴 풀이 모자라면 외형 중복 최소화, 성장하는 아트 팩으로 점진 확장.
- 런타임은 appearanceV2를 우선 표시하고 실패 시 기존 portraitId의 WebP로 자동 폴백.
- 레거시 세이브에 appearanceV2를 채울 때는 명시적 마이그레이션 후 저장하고, 기존 portraitId는 롤백용으로 유지. 현재 저장 키·version 1 검사를 함부로 바꾸지 않는다.
- 캐시 키: (artStyleVersion, faceId, headShapeId, bodyFrameId, hairStyleId, hairColorId, outfitId, accessoryIds, ageStageId, rendererVersion)의 안정된 해시. URL만 변경해 동일 ID를 덮어쓰지 않는다.

## 5. 전달/성능

- 소스 PNG·마스크는 제작 저장소/비공개 아트 폴더. 최종 승인 WebP와 매니페스트만 ImageKit 등 CDN으로 배포.
- 최초 화면은 하나의 최종 합성 WebP, 주변 NPC의 썸네일은 화면에 보이는 것부터 lazy-load. NPC 상세에서만 고해상도.
- NPC의 세이브에는 외형 데이터 ID와 버전만 저장하고 이미지 바이너리를 localStorage에 넣지 않는다.
- Canvas 실시간 편집은 소수의 파츠만; 긴 인물 목록에 Canvas 수백 개를 동시에 렌더링하지 않는다.
- CDN URL 실패/네트워크 단절 시 번들된 기존 WebP로 폴백. 깨진 이미지 아이콘, 흰 화면, 무한 재시도 금지.
- 이미지 파일 버전, 브라우저 캐시, WebP 압축률, iPhone Safari 메모리 소비를 검증한다.

## 6. QA 수용 기준

### 첫 품질 게이트 (게임 병합 금지)

- 남녀 각 1명 × 헤어 **형태** 2종 × 의상 **형태** 2종 = 8장. 같은 인물 사진 교체는 실패.
- 무손실 RGBA 합성 직후, 고정 얼굴 코어 마스크의 픽셀이 기준 원본과 **정확히 일치**해야 한다(손실 압축 WebP 이후 비교가 아님).
- 머리 실루엣·옷깃·앞/뒷머리 가림이 실제로 달라져야 한다. 채도/색상 필터만으로는 불합격.
- 8장 전부에서 얼굴·헤어·의상 충돌, 뒤틀린 귀/머리, 뭉개진 목, 갑작스러운 그림자, 어색한 경계가 없어야 한다(사람이 최종 승인).
- 남/여 태그와 승인 에셋의 내용 불일치 0건. 성별을 이미지 유사도 추정치로 자동 결정하지 않는다.
- 불량 에셋을 등록했을 때 UI에 나타나지 않아야 한다.

### 기기/세이브 게이트

- 실제 Safari 아이폰: 페이지 로딩, 조합 선택, 돌아가기, 기록, 상세 카드, 다중 NPC 표시, 캐시 실패 시 fallback 확인.
- 375px 및 430px 화면에서 가로 넘침과 컨트롤 가림 0건. 소스 이미지가 로딩 실패해도 앱이 죽지 않음.
- 동일 세이브/재로드/저장 내보내기·불러오기/보관 후 재회에서 faceId 불변. 새 게임에서는 다른 identitySeed 가능.
- 외형 선택 후 다른 인물 이미지로 완전히 바뀌는 현상 0건.
- GitHub Actions: 타입체크, 생성 규격/매니페스트 유효성/마스크 QA/선택 로직 회귀, Playwright WebKit 브라우저 스모크 테스트. 마지막으로 실물 아이폰 검수.

## 8. 비용과 리스크: 2026-10-22 확인 기준

- FLUX.2 [pro] 출력 1MP와 참조 이미지 1MP 편집 예시는 약 **$0.045/장부터**. 예시 비용 계산: 70개 에셋 × 3번 시도 × $0.045 = **$9.45**. 실제 입력 참고 이미지 수와 해상도, 모델, 리터치, 승인 불합격·재시도에 따라 달라진다.
- 시작 라이브러리 규모 예시: 성별 2 × [얼굴 8 + (두상 3 × 헤어 4) + 체형 3 + (체형 3 × 의상 4)] = **70개 원본**. 이는 70개 제작 목표이지 70장으로 모든 조합이 자동 품질 보장된다는 뜻은 아니다.
- 1000번 동일 수준의 1MP 편집이면 1000 × $0.045 = 약 **$45** (추가 참조·반복·인프라 제외). **NPC 1000명 = AI 호출 1000번**이 되어서는 안 된다.
- ImageKit 무료 플랜은 공시상 **매월 전송량 20GB, 저장 3GB**. 트래픽 한도 도달 시 제공 중지 가능하므로 캐시/폴백을 둔다.
- 주된 비용은 추론료보다 **얼굴 동일성/헤어라인/의상 경계 수작업 검수**일 수 있다.
- 무료 공개 플레이에서 AI 실시간 호출을 열지 않는다. 사용량 폭증과 키 유출·과금 리스크를 차단한다.

## 9. 남은 미결 사항

- 남녀 기본 외모의 반실사 디지털 일러스트 화풍을 **실사 사진과 분명히 구분**하여 확정.
- 3/4 뷰를 고정할지 정면을 고정할지 8장 첫 검증 기준으로 결정(혼용 금지).
- 얼굴 코어가 고정돼도 헤어라인·실루엣이 모두 호환되는지 실제 파츠 품질로 검증.
